# F1 26 (2026 Season Pack) UDP Support — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add parsing support for the F1 26 / "2026 Season Pack" UDP format (`m_packetFormat = 2026`) to the existing 2018–2025 parser.

**Architecture:** Each `binary-parser`-based parser class already handles all years via inline `if (packetFormat >= YYYY)` conditionals. We add `>= 2026` branches for the field-type/field-count changes, a `carCount(format)` helper to replace the scattered car-count literals across the 10 per-car array sites (22 → 24 for 2026), one new packet (`CarTelemetry2`, id 16), and updated Team/Driver ID tables.

**Tech Stack:** TypeScript, `binary-parser`, Jest, ESLint (`eslint-config-love`), tsx.

**Branch:** `feat/f1-26-support`. The weather-sample pre-fix is already committed (`89742fe`).

**Verification model (per user decision):** No real F1 26 capture exists yet, so there are **no new runtime tests** in this plan. The gate for every task is:
1. `npm run type-check` → passes (no TS errors)
2. `npm run lint` → passes (no eslint errors)
3. `npx jest` → still **139 passed, 0 failed** (no regression on 2018–2025)

`npx jest` is used (not `npm test`) to skip the auto-build/auto-lint hooks during iteration. Run `npm run lint` explicitly as shown.
